# Правила сопоставления данных (маппинг)

См. также: [архитектура процесса](03-architecture.md), [сценарии использования](01-use-cases.md).

Все правила ниже — настраиваемые (см. принцип "правила задаются настройкой" в
[архитектуре процесса](03-architecture.md#принцип-правила-переноса-задаются-настройкой-а-не-встроены-жёстко)).
Формулировки ниже описывают СМЫСЛ настройки, а не техническую форму, в которой
она хранится.

## 1. Определение типа объекта

Для каждой строки листа "Объекты" проверяется набор правил вида: *"если раздел
спецификации = X (и, возможно, дополнительные условия по другим столбцам) —
создать объект типа Y, взяв ключевое обозначение из столбца Z"*.

Особенности:

- **Одна строка — несколько объектов.** Строка может подходить сразу под
  несколько правил. Например, строка раздела "Изделия" может одновременно
  задавать организационную папку (контейнер, не входит в структуру состава) и
  реальный объект структуры (сборочную единицу) — тогда создаются оба.
- **Позиция без правила не создаёт объект.** Если строка не подходит ни под
  одно правило (типичный случай — раздел "Материалы", для которого нет
  типового правила создания объекта), объект по ней не создаётся, но код
  классификатора строки может быть использован дальше — как кандидат на
  материал по КД (раздел 3 ниже) или на вариант группы аналогов.
- **Папка и структура.** Если среди совпавших правил есть организационная
  папка, все НЕ-папочные объекты той же строки автоматически привязываются к
  этой папке. Сама папка не участвует в структуре состава изделия и не
  получает атрибутов (кроме обозначения).
- **Технологические детали.** Отдельные комбинации условий (например,
  "образец" технологического исполнения) создают объект типа "Технологическая
  деталь" вместо обычной детали — связь с такой позицией в структуре состава
  строится в обратном направлении (сама технологическая деталь выступает как
  инициатор связи), это требование целевой системы.
- **Стандартные и прочие изделия.** Позиции разделов "Стандартные изделия" и
  "Прочие изделия" с соответствующим признаком типа не создаются напрямую —
  их код классификатора ищется в справочнике материалов и классификаторов, и
  найденный элемент подключается к структуре как готовый объект. Не найдено —
  позиция не создаётся, перенос продолжается.
- **Классификация по коду.** После создания обычного объекта (кроме папок) его
  код классификатора дополнительно ищется в справочнике материалов и
  классификаторов — найденный элемент привязывается к объекту как признак
  принадлежности к номенклатуре. Это отдельное, необязательное действие: не
  найдено — объект остаётся созданным без этой привязки.

## 2. Атрибуты объекта

Список соответствий "столбец Excel → атрибут объекта в целевой системе"
задаётся: (а) общим списком для всех типов объектов и (б) дополнительным
списком для конкретного типа. Оба списка объединяются; при совпадении имени
атрибута побеждает список для конкретного типа.

- Для чисто организационных папок атрибуты не проставляются вовсе.
- Значение атрибута может проходить преобразование перед записью (например,
  "заменить любое непустое значение на фиксированную метку" — используется как
  флаг присутствия признака).
- Числовые атрибуты нормализуются (десятичная запятая приводится к точке) —
  значение, которое всё равно не читается как число, пропускается с пометкой в
  протоколе, а не блокирует создание объекта.

## 3. Связи состава (структура изделия)

По листу "Связи" пары "родитель–потомок" (по коду классификатора) превращаются
в связи состава между уже созданными объектами.

- **Количество.** Если столбец количества настроен, но значение конкретной
  строки не читается — связь не создаётся вовсе (без подстановки количества
  "1" по умолчанию).
- **Единица измерения.** Опциональна; резолвится через справочник по текстовому
  обозначению единицы (например "шт", "м2"). Список исключений (например "-",
  "компл") позволяет не резолвить единицу для отдельных значений.
- **Пара не нашлась.** Если код классификатора родителя или потомка не
  соответствует ни одному созданному на этапе 1 объекту — связь по умолчанию
  теряется (это нормально: часть строк листа "Связи" может ссылаться на
  позиции, которых нет на листе "Объекты", например на материалы).
- **Комментарий к связи.** Если на листе "Связи" настроен столбец с
  произвольным текстом (например "Комментарий") и указано, в какой атрибут
  связи его записывать (например "Примечание") — значение переносится на
  только что созданную связь состава. Правило применяется ко ВСЕМ связям без
  исключения, без фильтрации по типу родителя или потомка. Пустая ячейка —
  атрибут не проставляется, связь создаётся как обычно.

## 4. Материалы — три независимых источника

### Источник A: материал по чертежу (основной)

Для деталей читается обозначение материала по чертежу и код классификатора
материала. Поиск материала:

1. по коду классификатора в справочнике материалов — если найден и его
   наименование совпадает с обозначением по чертежу, материал считается
   определён;
2. если код пуст, не найден или не совпал — резолюция по имени в специальном
   разделе справочника "Материалы по КД";
3. если и обозначения по чертежу нет — материал для этой позиции не
   создаётся вовсе.

Детали с одинаковым кодом классификатора материала группируются — поиск
материала выполняется один раз на группу, но связь с деталью получают только
те детали группы, у которых собственное обозначение по чертежу заполнено.

### Источник B: материал-заменитель

Отдельный, независимый кандидат материала на ту же деталь, из отдельного
столбца "обозначение заменителя". Использует тот же код классификатора и тот
же справочник, что источник A, но собирается отдельным списком — чтобы
основной материал и заменитель одной детали не "схлопнулись" в один при
поиске. Если ячейка заменителя пуста — кандидат не создаётся.

### Группа замены материала

Если для одной детали успешно определены и основной материал (A), и
заменитель (B) — формируется формальная группа замены с двумя вариантами:
основной (базовый) и заменитель. Если определился только один из двух —
группа не формируется, создаются только обычные связи материалов.

### Источник C: материал по КД для изделий со своей спецификацией

Отдельный сценарий (см. также [этап 4 архитектуры](03-architecture.md#4-материалы-по-кд-для-изделий-со-своей-спецификацией)):
для сборочных единиц с признаком собственной спецификации, чьи потомки на
листе "Связи" не резолвились в объекты (типовая причина — раздел
"Материалы"), код классификатора потомка ищется в справочнике материалов —
без сравнения обозначения и без создания нового элемента справочника. Не
найдено — связь для этой пары просто не создаётся.

Материал источника C встраивается в структуру состава той же связью, что
обычная структура ("Состоит из ..."), а не отдельной связью материала к
детали, как источники A/B.

## 5. Заготовки и основной материал заготовки

Независимый поток (см. [этап 5 архитектуры](03-architecture.md#5-заготовки-и-основной-материал-заготовки)):
для деталей с заполненным кодом классификатора материала:

1. создаётся объект "Заготовка";
2. связь деталь↔заготовка строится в обратном направлении (заготовка —
   инициатор связи) — так сконфигурирован соответствующий тип связи в целевой
   системе;
3. к заготовке привязывается основной материал, найденный тем же способом,
   что источник C (только по коду, без сравнения обозначения); несколько
   заготовок с одинаковым кодом материала получают ОДИН и тот же объект
   материала — это ограничение целевой системы (нельзя создать второй объект
   материала на тот же элемент справочника);
4. на связь заготовка↔материал проставляется норма расхода (если столбец
   нормы настроен и значение читается как число);
5. на саму заготовку проставляются собственные атрибуты (например
   диаметр/длина/толщина — с фиксированной единицей измерения);
6. на связь заготовка↔материал проставляются атрибуты, которые могут отличаться
   между разными заготовками с общим материалом (например конкретный профиль
   отреза проката) — они настраиваются как атрибуты связи, а не атрибуты
   самого объекта материала, именно из-за общности объекта материала в пункте 3.

## 6. Литейные заготовки: комплекты вспомогательных материалов

Отдельный лист исходного файла. Родитель — любой объект, уже созданный на
этапе "Объекты" (тип объекта не имеет значения для этого потока). Для каждого
уникального родителя создаётся один "Комплект вспомогательных материалов", с
обратной связью на родителя. Строки делятся по типу материала:

- "Образец" — не обрабатывается;
- "Основной" — материал определённого типа, привязывается к комплекту прямой
  связью;
- "Вспомогательный" — материал другого типа, тем же способом.

На связь комплект↔материал проставляются норма расхода и цех-потребитель (если
заполнены).

Если родитель не найден — весь комплект и все его строки пропускаются. Если не
найден конкретный материал строки — пропускается только эта строка, остальной
комплект создаётся.

## 7. Вспомогательные материалы детали

Ещё один отдельный лист исходного файла, архитектурно идентичный разделу 6, но
без деления по типу материала (всегда один тип) и со столбцами родителя/
материала, определяемыми по названию столбца, а не по номеру буквы.

## 8. Группы аналогов

Для позиций листа "Связи" с заполненным признаком "группа аналогов" (формат:
номер группы – номер варианта) формируется группа взаимозаменяемых вариантов
состава — тот же механизм, что группа замены материала (раздел 4), но не
привязанный конкретно к материалам: группируются произвольные позиции состава
одного родителя.

Признак "основной вариант / заменитель" определяется по двум
производственно-количественным столбцам строки: оба ненулевые — основной
вариант, оба нулевые — заменитель. Если заполнено только одно из двух —
считается ошибкой исходных данных, строка не участвует в группе аналогов (но
её обычная структурная связь создаётся как обычно).

Если потомок варианта не был создан на этапе "Объекты" (типично — позиция
раздела "Материалы"), но при этом является частью группы аналогов — его код
классификатора дополнительно ищется в справочнике материалов и, если найден,
объект создаётся тем же способом, что материалы по КД. Это имеет приоритет
над источником C (раздел 4) — если позиция подходит под оба сценария
одновременно, обрабатывается как часть группы аналогов.

## Таблица: что настраивается без изменения самого инструмента

| Настраиваемый элемент | Что можно менять |
|---|---|
| Правила определения типа объекта | Условия отбора строк, целевой тип объекта, откуда брать ключевое обозначение и состояние объекта |
| Атрибуты объекта | Соответствие "столбец → атрибут", преобразования значения, признак числового атрибута |
| Связи состава | Название столбцов количества/единицы измерения, тип связи, список исключений единиц измерения |
| Источники материалов (A/B/C) | Столбцы обозначения/кода, целевой тип материала, тип связи с деталью, список атрибутов материала |
| Заготовки | Целевые типы объектов-кандидатов, типы связей, столбцы нормы расхода, списки атрибутов объекта/связи |
| Литейные заготовки / вспомогательные материалы | Название листа, столбцы, типы объектов и связей, названия атрибутов |
| Группы аналогов | Названия столбцов-признаков, шаблоны названий группы/варианта |
| Условия отбора строк | Новый вид условия (например, "заканчивается на") добавляется расширением списка доступных условий, без переработки остальной логики |
