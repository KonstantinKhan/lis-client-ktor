# Логирование и протоколирование результата

См. также: [архитектура процесса](03-architecture.md), [известные ограничения](06-known-limitations.md).

## Как это устроено сейчас

Во время выполнения каждого этапа переноса (см.
[архитектуру процесса](03-architecture.md)) инструмент сообщает о каждом
значимом событии по ходу обработки данных:

- позиция создана — какой объект/связь/материал и по какой строке исходного
  файла;
- позиция пропущена — с указанием причины (не найдено соответствие в
  справочнике, не читается значение количества, отсутствует обязательное
  условие для данного потока и т.п.);
- возникла ошибка на отдельной позиции — сообщение об ошибке, обработка
  остальных позиций продолжается;
- по каждому потоку обработки (материалы, заготовки, группы аналогов и т.п.)
  ведётся счётчик обработанных/созданных/пропущенных позиций.

Все сообщения выводятся в консоль в текстовом виде, в порядке возникновения,
вперемешку с прочими сообщениями хода выполнения. Разделения по уровню
важности (информационное сообщение / предупреждение / ошибка) и записи в файл
сейчас нет — если нужно сохранить протокол выполнения, пользователю нужно
самостоятельно перенаправить вывод консоли в файл при запуске.

## Что требуется (задел для проектирования)

Для полноценного протоколирования, пригодного как основание для приёмки
результата переноса и разбора инцидентов, ожидается:

1. **Уровни важности сообщений** — как минимум: информационное сообщение (что
   создано), предупреждение (что пропущено и почему), ошибка (что не удалось
   выполнить и требует внимания).
2. **Сохранение протокола в файл**, отдельно от вывода на экран, чтобы
   результат каждого запуска можно было просмотреть и приложить к отчёту о
   переносе постфактум.
3. **Единый формат записи** — чтобы сообщения одного вида (например, "позиция
   пропущена по причине X") были узнаваемы и, по возможности, разбираемы
   программно (для последующего анализа без ручного просмотра всего текста).
4. **Итоговая сводка по завершении переноса** — минимальный состав:
   - количество созданных объектов, по каждому типу;
   - количество созданных связей состава;
   - количество созданных материалов, по каждому из источников (по чертежу,
     заменитель, по КД);
   - количество созданных заготовок, комплектов, групп замены и групп
     аналогов;
   - количество пропущенных позиций, с разбивкой по причине пропуска.
5. **Привязка сообщения к исходной позиции** — по коду классификатора и/или
   номеру строки исходного файла, чтобы можно было найти конкретную позицию
   в исходном файле по сообщению протокола.

Это раздел для дальнейшей проработки аналитиком — состав полей сводки, формат
записи и способ хранения протокола (файл на диске, база данных, интеграция с
системой мониторинга) согласуются отдельно, в зависимости от требований
заказчика к аудиту переноса.
