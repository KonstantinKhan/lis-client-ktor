# Сценарии использования

См. также: [назначение и понятия](00-overview.md), [команды](02-commands.md),
[архитектура процесса](03-architecture.md).

## Действующее лицо

Специалист, ответственный за перенос спецификации изделия в PLM-систему. Один
сценарий использования = один запуск = перенос одного изделия (одного файла
спецификации).

## Сценарий 1. Подготовка исходных данных

Пользователь готовит файл спецификации в Excel со следующими листами:

- **"Объекты"** — построчный перечень позиций спецификации: обозначение,
  наименование, раздел спецификации, код классификатора, тип позиции, признак
  наличия собственной спецификации, атрибуты (масса, материал по чертежу и
  т.п.).
- **"Связи"** — пары "родитель–потомок" по коду классификатора, с количеством
  и единицей измерения — описывают, что из чего состоит.
- Дополнительно, при необходимости — отдельные листы для литейных заготовок
  (комплекты вспомогательных материалов для отливок) и для вспомогательных
  материалов детали.

Состав столбцов и их назначение (что откуда берётся) заранее согласовывается и
настраивается в конфигурации инструмента — см. [правила сопоставления](04-mapping.md).

## Сценарий 2. Запуск переноса

1. Пользователь запускает инструмент в рабочей папке, где лежит файл
   конфигурации переноса и указан путь к файлу спецификации.
2. Инструмент подключается к PLM-системе и к справочнику материалов, открывает
   рабочую сессию (аналог "черновика" изменений — до явного подтверждения
   изменения не видны другим пользователям PLM-системы).
3. Пользователь вводит команду запуска миграции (см. [команды](02-commands.md)).
4. Инструмент выполняет перенос последовательно, этап за этапом (см.
   [архитектуру процесса](03-architecture.md)), сообщая о ходе выполнения и
   фиксируя в протоколе (см. [логирование](05-logging.md)) каждую позицию:
   создана, пропущена (и почему), либо возникла ошибка.
5. По завершении пользователь явно подтверждает результат — только после этого
   перенесённые данные становятся видны остальным пользователям PLM-системы.
   Если сессию завершить без подтверждения, все изменения этого запуска
   останутся недоступны снаружи и будут потеряны при следующем запуске.

## Сценарий 3. Обработка неполных или противоречивых исходных данных

Общий принцип: **лучше пропустить позицию и зафиксировать это в протоколе, чем
создать её с неверными или неполными данными.** Примеры (подробнее —
[правила сопоставления](04-mapping.md)):

- Если для связи родитель-потомок задан столбец количества, но значение в
  конкретной строке не читается — связь не создаётся вовсе (не подставляется
  количество "1" по умолчанию).
- Если материал не находится в справочнике материалов ни по коду, ни по
  обозначению — позиция (деталь, заготовка и т.п.) всё равно создаётся, просто
  без материала.
- Если у изделия есть позиции без назначенного типа (например, позиции раздела
  "Материалы", для которых нет отдельного правила создания объекта) — такие
  позиции сами по себе не создаются, но их код классификатора всё равно
  учитывается там, где это предусмотрено (материалы по КД, группы аналогов —
  см. [маппинг](04-mapping.md)).
- Единичная ошибка на одной позиции не останавливает перенос целиком — перенос
  продолжается на следующих позициях, а ошибка фиксируется в протоколе.

## Сценарий 4. Повторный запуск

Инструмент не отслеживает, что уже было перенесено ранее — повторный запуск на
том же файле создаёт данные заново. Если предыдущий перенос завершился без
подтверждения (см. сценарий 2), его результат не виден и не мешает повторному
запуску, но занимает ресурсы PLM-системы как незавершённая сессия — до тех
пор, пока её явно не закрыть.

## Результат переноса

По завершении сценария 2 в PLM-системе появляются, в соответствии с исходными
данными:

- объекты структуры изделия (сборочные единицы, детали, технологические
  детали, стандартные и прочие изделия) со связями состава между ними;
- материалы (по чертежу и по коду классификатора), связанные с деталями и со
  своими заменителями;
- заготовки с назначенным основным материалом и нормой расхода;
- комплекты вспомогательных и литейных материалов;
- группы замены материалов и группы аналогов состава, где это предусмотрено
  исходными данными.

Итоговая структура доступна другим пользователям PLM-системы только после
явного подтверждения (см. сценарий 2, шаг 5).
