# Глоссарий

Доменные термины, встречающиеся в коде, `settings.json` и логах утилиты без расшифровки.

## Конструкторско-технологические термины

**ДСЕ** — деталь/сборочная единица; собирательный термин для позиции состава изделия
(в отличие от "материала" или "стандартного изделия"). Встречается в названиях столбцов
Excel, например "единица измерения входящего элемента в ДСЕ" (`linksSheet.unitColumn`).

**КД** — конструкторская документация. "Материал по КД" — материал, назначенный по
конструкторской документации детали/сборки (в отличие от материала по технологии
изготовления). Это же имя типа Loodsman, в который материализуются найденные/созданные в
ПОЛИНОМ элементы (`materials.materialTarget`).

**DS** — в данном проекте условное обозначение признака "у объекта есть собственная
конструкторская спецификация" (полноценный состав, заданный отдельно от родительского
изделия), настраивается через `mapping.bomMaterials.specificationConditions` (по умолчанию —
проверка значения `"DS"` в столбце "конструкторская спецификация" листа "Объекты"). Не
путать с ДСЕ (другое сокращение, другой смысл).

**Раздел спецификации** — стандартная (ГОСТ 2.106) классификация строки в спецификации
изделия: "Документация", "Комплексы", "Сборочные единицы", "Детали", "Стандартные изделия",
"Прочие изделия", "Материалы", "Комплекты" и т.п. В данном проекте столбец с этим значением
есть на листе "Объекты" (используется и в `types[].conditions` для выбора типа объекта, и в
`bomMaterials.materialConditions` для распознавания раздела "Материалы"), но ЕГО НЕТ на листе
"Связи" — реальный источник путаницы, зафиксированный в
[[03-external-api-quirks.md]].

**Сортамент** — здесь: способ идентификации материала по стандартизованному коду
(ГОСТ/классификатор), а не по произвольному текстовому обозначению. "Код классификатора
объекта который записан в поле сортамента" (`materials.classifierCodeColumn`) — конкретный
столбец Excel с таким кодом для основного материала детали.

## Код классификатора — омоним, два разных смысла

В проекте (и в исходных данных Excel) словосочетание "код классификатора" встречается в
**двух разных ролях**, которые легко перепутать:

1. **Код классификатора объекта** (`mapping.identifierColumn`, обычно столбец "код
   классификатора" на листе "Объекты") — идентификатор САМОЙ строки/объекта, используется
   для сопоставления родитель↔потомок на листе "Связи" (`linksSheet.parentColumnIndex`/
   `childColumnIndex`) и для признаков DS/раздела Материалы. Числовой (`Long`).
2. **Код классификатора материала "в поле сортамента"** (`materials.classifierCodeColumn`) —
   код КОНКРЕТНОГО МАТЕРИАЛА (не объекта-детали), по которому идёт поиск в справочнике
   ПОЛИНОМ "Коды". Строковый, хотя по формату часто тоже выглядит как число. Общий у основного
   материала и у заменителя (см. [[04-business-logic.md]], поток B).

Оба в логах/коде часто называются просто "код классификатора" без уточнения — при чтении
логов важно понимать, о какой из двух ролей речь по контексту (объект/связь vs материал).

## ПОЛИНОМ:MDM

**ПОЛИНОМ:MDM** — внешняя система управления мастер-данными (Master Data Management),
используется здесь как справочник материалов/классификаторов. Интеграция — отдельный REST
API (`polynom/client/`, `polynom/api/dto/`), отдельная авторизация (access/refresh токены),
отдельный семафор конкурентности от Loodsman.

**Справочник (reference) / каталог (catalog) / группа (group) / элемент (element)** —
иерархия ПОЛИНОМ сверху вниз: справочник содержит каталоги, каталог — группы, группа —
элементы (конкретные материалы). В `settings.json` задаётся именами (`materials.hierarchy`,
`materials.codesReferenceName`) — резолвится по имени в реальные `{objectId, typeId}`.

**Понятие (concept)** — отдельная сущность схемы ПОЛИНОМ, не то же самое, что
справочник/каталог/папка. Используется как `ownerScope` при поиске по свойству
(`search/execute-property-search`) — см. [[03-external-api-quirks.md]].

**Property-definition** — определение свойства в схеме ПОЛИНОМ (например, "код
классификатора" как атрибут элемента). Резолвится по `absoluteCode` из админки ПОЛИНОМ
(`materials.classifierCodePropertyAbsoluteCode`) либо задаётся напрямую id'ами
(`materials.classifierCodePropertyId`).

**Location** — служебная строка-идентификатор элемента ПОЛИНОМ, используемая при создании
связанного BO-объекта в Loodsman (`EditObject/create-bo-object`) — получается через
`classification/get-location`.

## Loodsman

**Чекаут (checkout)** — рабочая "корзина изменений" в Loodsman: пока сессия не сделала
`check-in`, все созданные/изменённые объекты не видны снаружи текущей сессии (даже в UI под
тем же логином). Открывается на корневом объекте миграции сразу после его создания.

**Проект (project, `isProject`)** — признак объекта верхнего уровня в дереве Loodsman,
отображается отдельно от структурных связей. В этом проекте ставится ТОЛЬКО на корень
миграции ("Миграция") — см. [[03-external-api-quirks.md]] про инцидент с задвоением.

**BO-объект** — объект Loodsman, интегрированный с элементом ПОЛИНОМ:MDM по `location`;
создаётся и связывается с элементом ПОЛИНОМ за один нативный вызов
(`EditObject/create-bo-object`).

**Группа замены / вариант замены** (`ObjectConfiguration/new-change-group-2`/
`new-change-variant-2`) — механизм Loodsman для формального описания взаимозаменяемости:
группа объединяет несколько вариантов одной и той же роли в структуре изделия (здесь —
основной материал и материал-заменитель одной детали), у каждого варианта — флаг "базовый"
(`isBasic`).

**"Материал по КД" vs материал-заменитель** — оба физически являются объектами одного и того
же типа Loodsman (`materials.materialTarget`, обычно "Материал по КД") и линкуются к детали
одним и тем же типом связи (`materials.detailLinkType`). Разница — не в типе объекта, а в
РОЛИ: основной материал резолвится из столбца `drawingDesignationColumn`, заменитель — из
`substituteDrawingDesignationColumn`; формальное различие между ними в Loodsman появляется
только на уровне группы замены (см. выше).

**`Unit`/`Measure`** — единица измерения и величина связи (`Состоит из ...`). `Unit`
("шт", "м2" и т.п.) устанавливается напрямую; `Measure` ("Количество", "Площадь")
выводится сервером Loodsman из выбранного `Unit` — отдельного API для прямой установки
`Measure` нет.
